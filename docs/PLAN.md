# Native MacVisio implementation plan

The user requires a complete native port of Visio Professional 2019 with reading and writing of **both VSD and VSDX**, and all Visio functions. A working editor milestone does not satisfy that acceptance target. The supplied Windows installer has been inspected and preserved; it contains no source project that can be built for macOS. See [installer findings](INSTALLER-INSPECTION.md).

## Completed implementation milestones

1. Native Swift/AppKit editor: document windows, canvas, library, text editing, geometry/formatting inspector, connectors, undo/redo, clipboard, pages, zoom, printing and exports.
2. Public VSDX import/export and source package preservation: supported edits patch original XML while retaining opaque parts; in-place VSDX document saves and native recovery include original package data.
3. Legacy VSD graphics import through a bundled native libvisio reader. Converted drawings can be edited and saved as real VSDX files. An experimental v11 binary writer now emits native saved graphics/text and checked MacVisio metadata. Unchanged external VSD exports preserve source bytes; changed binary semantics remain incomplete.
4. Expanded editable features: nested groups and transformations, custom paths, images, fonts/text blocks, layers, Shape Data, hyperlinks, cached connector routes, numeric ShapeSheet dependency calculation, VSSX master loading and VSTX drawing creation.
5. Reproducible release packaging, pinned ZIPFoundation dependency, bundled third-party reader/dependencies/licenses, model/editor/interchange tests, real-format fixtures and application render/launch diagnostics.
6. Inherited master-group expansion, partial subshape/row overrides, instance-scoped connections and formula references, minimal local save overrides, deletion tombstones and older-metadata reimport. See [MASTER-INHERITANCE.md](MASTER-INHERITANCE.md).
7. Connector hierarchy across import, transforms, clipboard, layer behavior and both public exporters; cached master ungrouping with retained glue; bounded shape-ID allocation; preservation of equivalent caches and numeric-looking text. See [GROUPED-CONNECTORS.md](GROUPED-CONNECTORS.md).
8. Connection-point rows, names/indexes, cached coordinates/formulas, port-specific VSDX glue, native grid editing/snapping, rename/delete with Undo, inherited deletion and metadata upgrade. See [CONNECTION-POINTS.md](CONNECTION-POINTS.md).

## Required work before claiming the requested port is complete

1. Complete the experimental binary VSD serializer and implement a richer importer with retained semantics. Verify Windows open/edit/save/reopen in each supported Visio generation; complete payloads, expressions, masters, data/glue and original-object edit preservation. The current encoder/graphics converter is not a verified full VSD implementation. See [BINARY-VSD.md](BINARY-VSD.md).
2. Establish a Visio Professional 2019 Windows comparison environment matching the installer build, plus representative user files. Build a feature inventory and test every workflow; compare public file content, rendered pages, save/reopen and editing behavior. The existing QEMU Windows guest is identified and reachable, but Visio is not installed or registered, so Visio acceptance remains blocked on obtaining a supported installation.
3. Complete ShapeSheet, geometry/control handles, master inheritance and instance updates, rich text, backgrounds, themes/effects, connection ports/routing, image/metafile/OLE handling and the installer libraries. Resolve the itemized gaps in [COMPATIBILITY.md](COMPATIBILITY.md).
4. Implement the specialist solutions: diagram semantics and validation, data graphics/linking/refresh, containers/lists, reports, engineering scales/measurement, CAD, org-chart/data import, automation compatibility and integrations.
5. Run differential regression tests on the full fixture/workflow inventory. Complete manual native UI tests, printing/recovery tests, accessibility, performance and supported OS/architecture testing; configure distribution signing/notarization when distribution is required.

These stages require substantial further engineering and validation. The absence of a Visio-enabled Windows comparison environment does not prevent continued implementation, but it prevents a substantiated claim of full behavioral and file compatibility. No estimated completion date or full-parity claim is supported by the current evidence.

The bounded compatibility work imports VSDX themes and selected color/style variations, resolves supported palette `THEMEVAL` selectors, implements limited `THEMEPROP("Embellishment"/"MultiFormat")` with inherited page selectors, and evaluates typed theme colors with selected `RED`/`GREEN`/`BLUE`, `HUE`/`SAT`/`LUM`, `RGB`, palette-limited numeric `HSL` and `LUMDIFF` calculations. `RGB` and `HSL` return numeric palette indexes only for colors already present in the evaluator's palette; allocating or merging custom palette entries remains open. Type-specific display formatting, locale behavior, non-palette theme values, theme rendering, custom palette writing/merging, complete ShapeSheet semantics and Visio-side validation remain open. 7. The bounded ShapeSheet increment implements `BITAND`, `BITOR` and `BITXOR` in the scalar and typed evaluators for exactly two unitless, finite whole-number operands from 0 through 65535, returning an unsigned 16-bit result. Regressions cover Microsoft's documented 12/6 examples, zero and maximum masks, nesting, arity, invalid values and unit rejection; all 368 Swift tests pass. The functions reject invalid inputs so cached values can be retained; signed masks, coercion, shifts, `BITNOT`, Visio-specific error tokens and full ShapeSheet semantics remain open. See [ShapeSheet numeric functions](NUMERIC-FUNCTIONS.md) and Microsoft's [BITAND](https://learn.microsoft.com/en-us/office/client-developer/visio/bitand-function), [BITOR](https://learn.microsoft.com/en-us/office/client-developer/visio/bitor-function) and [BITXOR](https://learn.microsoft.com/en-us/office/client-developer/visio/bitxor-function) references.
8. The next bounded theme increment imports effect and connector `lnStyleLst` widths/caps plus Visio `lineEx` extension records, and resolves `THEMEVAL("LineWeight")`, `THEMEVAL("ConnectorWeight")`, `THEMEVAL("LineCap")`, and host-cell `THEMEVAL()` through the selected component scheme and QuickStyle line matrix. It covers direct matrix values 1–6 and the 100–103 variation selectors, with real VSDX fixture tests for widths, cap enum values, component selection, fallback and invalid selectors. The package inventory baseline has 16,938 LineWeight, 24,351 LineCap, 16,957 LinePattern and 21,185 Rounding evaluation failures across the installer set. Pattern, rounding, arrows/sizes and other extension properties remain unsupported: the imported `lineEx` data is retained, but the public schema does not define the record offset needed to map those values exactly to the chosen matrix. Full theme/component matching and connector formulas in edge objects remain open. See [ShapeSheet numeric functions](NUMERIC-FUNCTIONS.md), Microsoft's [THEMEVAL](https://learn.microsoft.com/en-us/office/client-developer/visio/themeval-function), [QuickStyleLineMatrix](https://learn.microsoft.com/en-us/openspecs/sharepoint_protocols/ms-vsdx/edfd9f33-fea3-4bf5-8cd5-a91a3d677b03), [QuickStyleType](https://learn.microsoft.com/en-us/openspecs/sharepoint_protocols/ms-vsdx/550dd5fb-2388-41c9-867d-3a8af03c94b8) and [dynamic theme components](https://learn.microsoft.com/en-us/openspecs/sharepoint_protocols/ms-vsdx/cd5bb66b-7f2f-49b5-a630-9ae976bbdb26).
