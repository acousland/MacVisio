# ShapeSheet numeric functions

`RGB(red, green, blue)` validates three unitless whole-number channel values from 0 through 255 and returns the matching index in a Visio color palette. The scalar and typed evaluators share a `ShapeSheetColorPalette`: it knows the fixed 24-color Visio palette and reuses matching indices. App ShapeSheet contexts seed it from an imported VSDX document's `ColorEntry` table; VSSX stencil import uses that stencil's table to cache supported RGB formulas before detaching its master fragments. If a color is absent, evaluation throws and the imported cached value is retained instead of returning an undefined index. MacVisio does not allocate palette colors, merge stencil palettes into a destination document, or rewrite `ColorEntry` entries, so a detached stencil formula may remain unevaluated in a host drawing whose palette lacks that custom color. This follows Microsoft's [RGB reference](https://learn.microsoft.com/en-us/office/client-developer/visio/rgb-function-visioshapesheet) and the fixed indices in the [VSDX color table specification](https://learn.microsoft.com/en-us/openspecs/sharepoint_protocols/ms-vsdx/1fac45bf-ef10-4b29-ada1-4acf47fed340). Fractional channel coercion is not specified by the reference and is rejected.

`SIGN(number, fuzz)` accepts one or two arguments. When omitted, `fuzz` defaults to `1E-9`; a number whose absolute value is at most the fuzz threshold returns `0`, while values above and below the threshold return `1` and `-1`. Supplying zero fuzz gives an exact sign comparison for nonzero values. Microsoft's [SIGN reference](https://learn.microsoft.com/en-us/office/client-developer/visio/sign-function) documents the optional parameter, its default, and the default-versus-zero examples. The reference does not specify the exact equality boundary; this evaluator treats `abs(number) == fuzz` as zero.

Typed calculations return a unitless sign. A unitless fuzz is compared in the ShapeSheet numeric scale of the first argument. If fuzz has a unit, the number must also have a compatible dimension. Negative fuzz is rejected because it cannot represent a nonnegative distance from zero; non-finite values are rejected as well.

The installer library/template formula scan found 280 one-argument and 101 two-argument `SIGN` calls. Tests read `Height+SIGN(Height,0.01)*0.14` from the actual installer `HVACC_U.VSSX` stencil and evaluate it with a height within the tolerance. This demonstrates formula coverage for that expression, not full template behavior.

The bounded numeric evaluator also supports `CEILING` and `FLOOR` with one argument or a number and a multiple. `CEILING` rounds away from zero; `FLOOR` rounds toward zero. With one argument the multiple is 1. A zero number or multiple returns 0. Nonzero arguments must have the same sign, as in Microsoft's [CEILING](https://learn.microsoft.com/en-us/office/client-developer/visio/ceiling-function) and [FLOOR](https://learn.microsoft.com/en-us/office/client-developer/visio/floor-function) references. Typed calculations retain the first argument's unit when both arguments use compatible units; a unitless multiple is interpreted in the first argument's unit. The scalar geometry/control evaluator returns a number. Non-finite inputs, overflow and incompatible typed units are rejected.

`BITAND`, `BITOR` and `BITXOR` accept exactly two unitless, finite whole-number operands from 0 through 65535 and return the corresponding unsigned 16-bit bitwise result. This bounded contract follows Microsoft's [BITAND](https://learn.microsoft.com/en-us/office/client-developer/visio/bitand-function), [BITOR](https://learn.microsoft.com/en-us/office/client-developer/visio/bitor-function) and [BITXOR](https://learn.microsoft.com/en-us/office/client-developer/visio/bitxor-function) references, which specify 16-bit binary operands and give `12`/`6` examples. Fractional, negative, over-range, unit-bearing and non-numeric operands, and wrong argument counts, are rejected so a caller can retain the imported cached value. The evaluator does not implement signed masks, coercion, shifts, `BITNOT` or Visio's specific error tokens.

`THEMEGUARD(value)` evaluates to the value of its single argument, retaining its type in typed calculations. This follows Microsoft's [MS-VSDX function-token definition](https://download.microsoft.com/download/C/6/C/C6C3C6F1-E84A-44EF-82A9-49BD3AAD8F58/SharePoint/%5BMS-VSDX%5D.pdf) (§2.5.3.157). A test evaluates the actual installer formula `THEMEGUARD(RGB(0,0,0))` from `BLDCOR_M.VSSX`. The formula is preserved during normal recalculation, but `THEMEGUARD` is not treated as the edit lock provided by `GUARD`; manual geometry edits may replace it. This only implements the value calculation. It does not resolve or apply dynamic theme formatting, and Microsoft notes that manual formatting overrides `THEMEGUARD` unless the formula also uses `SETATREFEXPR` ([THEMEGUARD reference](https://learn.microsoft.com/en-us/office/client-developer/visio/themeguard-function)).

`THEMEVAL(theme_value, default)` evaluates its second argument only when the formula host shape has an explicit, literal `ColorSchemeIndex=0`. Microsoft documents that the default applies when no theme is applied, and that `ISTHEMED()` is false when a shape's `ColorSchemeIndex` is zero. Positive, inherited, formula-derived, missing, and page-hosted theme states remain unsupported so their cached values are preserved. This does not read theme package parts or implement one-argument or host-cell `THEMEVAL` ([THEMEVAL](https://learn.microsoft.com/en-us/office/client-developer/visio/themeval-function), [ISTHEMED](https://learn.microsoft.com/en-us/office/client-developer/visio/isthemed-function)).

`ISTHEMED()` returns whether the host shape's `ColorSchemeIndex` is greater than zero. An explicit zero returns `FALSE`; positive values return `TRUE`. A shape-hosted call reads the formula's host shape and does not consult the document or page theme, as specified in Microsoft's [ISTHEMED reference](https://learn.microsoft.com/en-us/office/client-developer/visio/isthemed-function). The [ColorSchemeIndex reference](https://learn.microsoft.com/en-us/office/client-developer/visio/colorschemeindex-cell-theme-properties-section) identifies the shape's cell; the [MS-VSDX definition](https://learn.microsoft.com/en-us/openspecs/sharepoint_protocols/ms-vsdx/1e7e9b7e-d116-41c0-9c53-5e57c26042a4) describes its encoded values. The function documentation does not specify the result when that cell is absent, so MacVisio leaves that case unsupported and retains the cached value. Theme package parts remain opaque; theme resolution is limited to the guarded two-argument `THEMEVAL` default described above.

The evaluator reports a calculation issue for unsupported argument counts and invalid inputs. It does not produce Visio's specific `#NUM!` or `#VALUE!` tokens. Other documented rounding and math functions, including `ANG360`, `TRUNC`, `LOG10`, and the hyperbolic functions, remain unsupported.
