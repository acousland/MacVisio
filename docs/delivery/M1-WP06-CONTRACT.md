# WP-06 runtime and change-set contract

The bounded children remain the WP-06 slices in `M1-IMPLEMENTATION.md`: identity/hierarchy/graph ownership, atomic structural updates, bounded property updates; conservative spatial bounds, drawing-order queries, local snapping; committed change sets and presentation-only events. These files implement the standalone interface and indexes. Document/Canvas command integration and acceptance evidence belong to the milestone owner.

## Ownership and dependencies

`Diagram`, `DiagramPage`, node/edge values and source archives retain their interchange representation. A document owns committed state, revision/state identity and undo. A document-owned, serially confined `PageRuntime` owns disposable indexes for one committed page. Preview geometry, selection, viewport and presentation events belong to the editor/canvas. Neither runtime file imports AppKit, evaluates a formula, decodes an image, reads a file, or mutates a model. Source identity is untouched.

All runtime geometry is in page/drawing units, before `paperScale` and canvas zoom. Callers convert screen tolerances by `coordinateZoom`; paper-sized stroke/shadow padding is divided by `paperScale`. Existing `DiagramCoordinates` owns interchange parent/page conversion; model group descendants already contain page coordinates and must not receive a second parent transform. These are named boundaries rather than a new wrapper around every existing coordinate.

`DocumentChangeSet.between(old,new)` runs at the calculation-input and calculated-commit boundaries; a normal replacement can run both diffs. Its full value diff is O(nodes + edges) plus model equality work; this cost is explicit and does not claim an incremental command diff. Per-page sets separate inserted/deleted IDs from changed IDs and identify geometry, ordering, hierarchy, layer and page-property effects. Page insertion/deletion is represented by document page sets; `pages` contains changes to existing pages. Document structure, properties, source resources and active-page changes are separate. `hasSemanticChanges` excludes activation and source-resource-only rebasing. `DocumentPresentationEvent` carries selection, viewport, preview and activation without requiring calculation or a semantic diff.

## Index updates and work evidence

`PageRuntime.apply(page:changes:preparedRoutes:)` requires the exact diff from its prior committed page. It invokes no callback and is published only after the enclosing commit updates all derived owners. Arbitrary insert/delete/reorder/group/DisplayMode/kind/layer/page-scale changes rebuild the indexes once. Unchanged topology permits ID-indexed replacement of changed properties, inherited eligibility for affected descendants, endpoint adjacency repair and incident-route invalidation. An invalid count/changed-ID mapping falls back before mutation. The runtime is not shared across concurrent tasks; immutable model snapshots cross job boundaries.

The bounded append child adds one exception: root, non-group, non-swimlane nodes appended as the complete source suffix can be installed without rebuilding old bounds or ranks. `PageChangeSet.between` certifies the unchanged source-order prefix in `appendedNodeIDs`; this proof uses the existing full committed diff and does not make that scan free. The runtime checks page/object counts, ordered suffix IDs, absence of existing-node/edge/property/hierarchy changes and each candidate's root/foreground eligibility before mutation. Existing paint-order ranks remain stable; new foreground nodes are appended above existing content. Other edits retain the full-rebuild fallback. Existing malformed cycles or an append resolving an orphaned hierarchy parent also force that fallback, preserving full drawing/eligibility behavior.

Indexes include UUID-to-value/source-index maps, parent/child membership, endpoint adjacency, cycle-safe descendant lookup, selected-ID intersection, cached inherited visibility/lock/snap permission, current `ShapeDrawingOrder` and complete paint order (swimlanes, connectors, foreground shapes). A parent disabling snap conservatively disables snapping for descendants. Selection expansion returns current IDs only; there are no references to deleted node IDs in endpoint adjacency. Structural undo uses the same replacement path.

`RuntimeUpdateWork` records node, edge, ancestor eligibility and spatial-entry updates and whether a rebuild occurred. `appendCandidateVisits` separately counts suffix-validation node reads, including a rejected attempt before fallback. `RuntimeQueryWork` records buckets, unique broad-phase candidates, overflow and full-scan fallback. Counts describe object/index operations, excluding the deliberately full committed-model diff and container allocation/copy-on-write work. A 2,000-node property-edit regression expects one node/spatial update and zero hierarchy/edge visits. The append regression compares a two-node append on 1,000- and 20,000-node pages: both require two suffix validations, two node/bounds/spatial updates, two root eligibility visits and no edge visits in the edge-free fixture. It compares all public indexes/bounds/order and sampled hit/snap queries against a fresh runtime. This does not claim bounded routing when geometry changes route obstacles.

## Conservative spatial queries and narrow phase

The node bound contains the rectangle, custom Bezier control-point hulls, built-in outsets, flips and rotation, text-block/person-text bounds, strokes and screen shadow padding. Uniform buckets have a default 256 drawing-unit cell. An object covering more than 64 buckets enters overflow and participates in each query; a query spanning more than 4,096 buckets uses an explicitly counted full scan. Zero-area point queries and inclusive boundaries are supported. Dense/giant overlapping content can require global candidate work; no spatial index promises locality in that case.

`nodeCandidates(at:)` returns visible nodes in reverse actual paint order. `nodes(intersecting:)` returns current paint order by default. Hidden DisplayMode=0 group outlines do not enter node hit/marquee candidates. These are conservative broad phases; a caller performs exact containment against prepared paths and existing special-case hit policy. A broad-phase bound must never itself become an exact hit result. Mixed node/edge dispatch uses `paintOrder`; independently preferring every node to every edge would still mishandle a swimlane under an edge.

Routes are accepted only as already prepared page-coordinate polylines. The runtime never invokes the formula-bearing connection geometry/router. Missing/invalid routes and connector labels without measured text bounds use overflow, so they are never omitted. Supplied label-free routes receive conservative arrow/stroke padding. `installPreparedEdgeBounds(_:)` accepts revision-current renderer bounds including measured labels, strokes and arrows, replacing this overflow with indexed geometry without changing semantic state. Any node geometry edit invalidates bounds of all prepared automatic orthogonal routes because any node can be an obstacle; incident straight/imported routes are also invalidated. A renderer can supply fresh routes in the same update or a later route-only update. Until then, overflow can make connector candidate queries O(edges); the counter exposes this limitation. Rendering integration must use revision-current prepared routes for exact connector containment.

A root append is also a new route obstacle. Its runtime update visits and invalidates prepared automatic-route bounds plus any edge whose previously free endpoint now attaches to a new UUID; unaffected prepared straight/imported bounds remain installed. A private reverse endpoint index retains missing-endpoint membership without exposing dangling node adjacency. Invalidation visits are included in `edgeVisits`/`spatialUpdates`; an unprepared route already in conservative overflow needs no redundant invalidation visit. Supplied fresh routes can replace invalidated bounds in the same update. The route regression checks exact counts and conservative equivalence with a fresh runtime under the same prepared-route availability.

## Snapping locality

Snapping uses rotated geometric rectangle bounds and excludes selected, invisible, effectively locked and snap-disabled shapes. A target participates only if its rotated bounds intersect the moving selection bounds expanded by `max(locality,tolerance)`, with default locality 160 drawing units. Thus a shape thousands of units away sharing one alignment axis does not attract the selection. Candidates retain source order so equal-distance tie behavior in `ShapeSnapping.alignmentDelta` remains deterministic. The conservative reference scan applies this same locality policy. The regression compares candidate IDs and resulting alignment delta, including hidden/locked/no-snap targets and a distant aligned target.
