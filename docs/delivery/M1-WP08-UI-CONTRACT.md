# WP-08 persistent editor presentation

This is the bounded WP-08-T04 implementation in `EditorUI.swift`. Rendering, semantic transactions and calculation remain owned by their respective runtime contracts.

The inspector creates at most three layouts per editor: page, node and connector. Controls and their targets survive refreshes and mode changes. A same-mode selection or property change updates values in existing controls without removing/recreating their view tree. Mode switches detach the previous views and attach the cached mode, so stale controls are excluded from accessibility and current-field lookup. Existing focused-field-editor and untouched-displayed-value commit guards remain intact.

Multiple selection compares underlying values before formatting numbers. Mixed text/numeric values use a `Mixed` placeholder and empty displayed baseline; untouched actions remain no-ops. Mixed checkboxes use the native mixed state; mixed popups use a disabled placeholder, preserving normal item indices. Mixed color wells draw a dash and expose the mixed state through accessibility. An explicit edit still uses the existing one-transaction selection command and undo behavior. Locked shapes retain the command layer's protection.

Page tabs retain their buttons by page UUID across activation, renaming, geometry changes and layout. Deleted-page buttons and saved view state are removed. View state per page stores current selection, connector, zoom, canvas scroll origin and inspector scroll origin. `capturePageViewState()` is called before activation; `restorePageViewState(for:)` restores current IDs only and reports whether a state existed. The milestone owner wires page switching to fit only pages without a stored state. This view state is editor-owned and is not encoded in the document or put on the undo stack.

Page switching completes the active field editor while the original page and selection remain current. Save finalizes an active inspector field editor before capturing its immutable model snapshot, without changing focus when no inspector field editor is active. Four added regressions cover edited page-name/node-text fields through actual `switchPage` and small-document native asynchronous Save/readback. For large documents, field finalization can submit an owned calculation job: explicit Save must coordinate that completion before promising to include the active text; the synchronous field-order tests alone do not establish that guarantee.

Stencil layout only positions retained visible rows. Filtering changes row attachment and reuses native shape/master cards by kind/definition UUID; updated definitions refresh the existing master card, while unloaded definitions are evicted. Filtering still scans available definitions once when its inputs change. It is not a virtualized list; very large displayed libraries still have one view per visible item. This keeps the existing stencil interaction and drag source behavior intact.

`layoutsCreatedCount`, `pageButtonsCreatedCount` and `cardsCreatedCount` are deterministic allocation-work evidence. `RetainedEditorUITests` checks 30 selection cycles, 20 repeated page layouts, 30 stencil layouts and filter roundtrips without allocating replacements, plus cached modes, mixed/no-op/edit/undo behavior, focused text editing, page-state restore and stale-selection pruning. These counters measure control creation rather than process memory. Image/undo/job resource budgets and rendering work are verified by the other WP-08/WP-09 owners.

Verification is pending the milestone owner's grouped compile and tests; no competing Swift build was run by this child. These changes alone do not claim full M1 acceptance or public interchange qualification.
