## Measured grouped7 observations

On `macmini.local`, macOS 27.0.1 (26A434), `build/m1-evidence/lifecycle-memory.json` recorded twenty cycles, 64 shapes and eight edits per cycle. Every closed document released, source bytes were preserved and each save installed exact binding originals. The imported source retained approximately 2.74 MB per open document, including a 2 MiB opaque part. Process RSS was 423,034,880 bytes at the pre-cycle baseline, peaked at 413,270,016 bytes among post-cycle samples and ended at 413,270,016 bytes. The post-cycle least-squares slope was +13,760 bytes/cycle. Allocator settling can make the pre-cycle baseline higher than every later sample; neither a negative baseline delta nor this small positive slope proves absence of leaks. Raster retention and 100-group undo/redo passed separate tests in the same process.

`build/m1-evidence/metadata-probe.json` compared the envelope-discriminator step on 8,412,826 synthetic JSON bytes (5,000 nodes), after one warmup with five measured samples. The full-object `JSONSerialization` discriminator median was 11.622 ms; the header-only loader median was 4.766 ms. This is the measured removal of a duplicate object-materialization step, not a claim about total model-import speed or all documents.

## Recovery fixture disposition and added coverage

The prior-binary focused run `runtime-render-debug2.log` retained a failure in `SavePreservationRebaseTests.testRecoveryAutosaveAcknowledgesOnlyRecoveryState`: NSCocoaError 512 when forcing `autosaveElsewhereOperation` to a temporary URL on an already-saved document. The local SDK's `NSDocument.h` and Apple's [autosave operation documentation](https://developer.apple.com/documentation/appkit/nsdocument/saveoperationtype/autosaveelsewhereoperation) distinguish untitled recovery from autosave-in-place. The fixture now creates a genuinely untitled changed document, verifies `autosavedContentsFileURL`, checks independent recovery/dirty identity and uses the inherited recovery initializer to read it. This corrected fixture awaits grouped validation; the failed run is not recorded as success.

The SDK audit also found that NSDocument defaults `autosavesDrafts` to true and uses `autosaveAsOperation` for a new current draft. This operation must establish the current source baseline and acknowledge its exact state, rather than leave `hasUnautosavedChanges` true. The parent added that current-file operation and limited application recents to explicit Save/Save As. `testUntitledDraftAutosaveEstablishesCurrentSourceAndAcknowledgesOnlyCapturedState` requires the exact state UUID/revision to survive, current URL and clean autosave identity to be established, later ordinary edits to remain dirty, and an external atomic replacement to produce a typed conflict while preserving both source bytes and local edits. Execution is pending the grouped run.

An inventory found no existing regression establishing pre-replacement external-write detection or a real interrupted staging writer followed by fresh-process checkpoint readback. `ExternalWriterRecoveryTests` adds those bounded checks. A real `/bin/cp` writer changes the source after capture; direct and queued save APIs must refuse a stale baseline, including a symlink target. A separate Save As preserves both external and local versions. Explicit revert must read the external model/opaque parts and reset stale dirty/undo state.

The interruption fixture autosaves an untitled edited document to a checkpoint and records original URL, checkpoint URL, exact state UUID and an unsaved marker in a test manifest. A real shell child reaches partial sibling output, is terminated, and the atomic writer must preserve the previous destination. A fresh built `MacVisio --convert` process reopens the identified checkpoint and writes public VSDX containing the unsaved text. These are added tests awaiting execution. They do not test abrupt termination of the installed app, automatic recovery registration/discovery or the macOS relaunch recovery UI.

Limits to retain in the final evidence:

- A queued cancellation completes when a worker reaps it; behind blocked workers its progress panel may remain visible. The retained queue remains bounded at 32. Running jobs complete cleanup before delivery.
- Export batch targets do not bound a single complex object, scene field-resolution step or runtime setup. `maximumMainStepSeconds` and `maximumObjectSeconds` expose those observations.
- Undo retention charge intentionally overcounts shared source bytes. It is a documented conservative accounting policy, not exact allocator memory. A single current action over 64 MiB remains undoable and reports `oversizedSingleAction`.
- The twenty-cycle RSS fixture has 64 shapes, eight edits per cycle and a 2 MiB opaque source part. It creates no editor windows. Raster retention is exercised separately with twenty distinct 1024² decoded images. RSS includes process/allocator/OS behavior and is not proof of absence of leaks.
- Parser success, private metadata, task counts and source equality do not qualify Windows Visio interoperability.
- Source metadata fingerprints can miss a writer preserving inode, byte count and modification time; an uncoordinated writer may race after the final check. No content-hash or exclusive-filesystem-lock claim is made.
- Installed-app/macOS recovery restoration remains separate from local NSDocument recovery initialization and the explicit fresh CLI checkpoint probe.
- Recovery initialized with a distinct original URL lacks a persisted original-file metadata baseline; its same-original save conservatively conflicts while Save As remains available. This case has no same-original-save acceptance claim.
