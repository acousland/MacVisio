### Native implementation and bounded evidence

`showDocumentFind(_:)` opens a retained per-editor native panel with query, case and content-scope controls, cross-page results, contextual snippets, a selectable logical-source preview, Previous/Next, replacement text and Replace Selected. Query changes invalidate old results. Search uses the accepted bounded lifecycle queue (the existing `library` job category), captures only immutable committed values, checkpoints between pages, and accepts results only for the current owner/state/revision/request. A cancelled job cannot publish late; scanning within one page currently finishes before the next cancellation checkpoint. Result completeness and invalid limits are visible. Native preview selection uses the exact source UTF-16 range; it has no editor-only empty-field placeholders to mis-map.

Background completion highlights the first table result and its source preview only. It never navigates, finalizes unrelated parent input or steals document focus. Explicit row action/selection or Previous/Next navigation first finishes parent native input, then rechecks exact result identity before activating the stored page through `switchPage` and using retained scene/runtime IDs and bounds to select and reveal the shape or connector. A later inline edit can commit and invalidate the result without navigating to an obsolete target. Page activation stays a presentation event. Hidden-layer results are identified without changing layer visibility. Both panels are associated with their owning editor, hold weak document/editor references, observe parent-window closure, and cancel/disable when its accepted lifecycle owner closes. No parent stored-property or teardown patch is needed.

Selected replacement revalidates owner, current committed state/revision, calculation availability, exact source bytes, UTF-16 boundaries, protections and fields immediately before submitting one validated candidate through `replaceInEditor`. The accepted transaction owns calculation and one undo group. Large-document replacement leaves the committed snapshot unchanged while calculation is pending and disables another replace; the panel explicitly asks the user to Find again after completion. A no-op candidate makes no transaction. Source preview/navigation does not start a separate inline-text edit. Idle availability refresh caches the exact owner/state/revision/result-input/selected-match/search/calculation key, avoiding repeated Unicode/run walks while unchanged; execution always revalidates directly.

`showCommandSearch(_:)` opens a native filter/table/action panel. Its curated catalog covers find, tools, editing, arrangement, protection, pages, zoom/grid, subprocess/off-page authoring, reversible drawing preview, shape-library visibility, content checks and redacted support export by routing to existing controller selectors. Enabled-state explanations check current selection counts, shape/group/layer locks, inherited/unknown text protection and missing field mappings for text/field commands, grouping eligibility, page count, accepted pending-calculation state and existing menu validation. Availability refreshes while the panel is open, caching reasons against document/page/selection/calculation/composition/filter identity and updating table cells only when those inputs change. Execution always revalidates the selected command directly. Query/filter disagreement refreshes results and requires review instead of executing an older displayed command. Native marked text cannot trigger command execution. Explicit opening during parent text composition is rejected with an explanation. Native Escape routing is left to the responder chain; panel cancellation cannot close over marked text. No global event monitor, canvas override or letter shortcut is added.

## Integration contract

`DocumentSearch.find(Query, in:)` returns a `Results` random-access collection. Each match carries stored page/object IDs, an explicit text/shape/data surface, UTF-16 range and the exact source string. Results follow stored page, node, surface and connector order. Each stored background page is searched once. Hidden and locked objects remain discoverable; visibility and edit eligibility are separate concerns. Shape search covers kind title, object UUID and preserved source ID. Data search covers property key, label and value; connector labels are searchable text.

Queries use fixed `en_US_POSIX` case-insensitive matching by default, with an explicit case-sensitive option. Empty queries/domains produce complete empty results. Nonoverlapping matches cover whole grapheme clusters; a query for one scalar inside an emoji/flag/combining cluster produces no partial-cluster match. AppKit selection offsets come directly from the source UTF-16 string, including canonical-equivalent accent matches.

`Query.maxResults` defaults to 10,000; accepted explicit budgets are 1...100,000. `Results.completion` is `complete`, `truncated` or `invalidBudget`. Invalid budgets return no matches with `invalidBudget`; a limit becomes `truncated` only when one extra accepted match proves incompleteness. Callers must surface that state rather than claim the whole document has been searched. Boundary checks walk forward as needed and stop with the result budget, without allocating an index for all text characters.

`DocumentSearch.replacementBlock(for:in:)` supplies actionable disabled-state reasons. `replacing(_:with:in:)` revalidates the current snapshot and returns a candidate value. It supports shape text and connector labels; shape identity and shape-data surfaces support navigation only. Typed data conversion, formulas and data editing require a separate committed edit. Stale source strings are compared by exact UTF-8 bytes, so canonically equivalent text with different UTF-16 offsets cannot reuse an old match. Invalid, empty, overflowing or partial-grapheme ranges are rejected.

Replacement checks current shape/group/layer locks, inherited `LockTextEdit`, duplicate/missing target and ancestor IDs, cycles, malformed run mappings and unmapped fields. Formula-dependent protection is blocked pending accepted calculation evidence rather than treating a cached false value as authoritative. Matches intersecting a nonempty text field, or crossing an empty field, are rejected. Adjacent fields, field tokens/definitions, character/paragraph source indices, requested font names, opaque style cells and unrelated sheet metadata are retained. Replacement text inherits the first selected character and paragraph styles. Exact no-op text replacement retains the original snapshot. Unselected runs retain their boundaries; replacements never flatten the whole rich-text string.

`FontSubstitution` accepts an injected catalog of installed font names, an ordered fallback list and optional explicit aliases. Exact installed spelling wins, then case-folded installed names, explicit alias order, fallback order, and finally the `System` rendering sentinel. Ambiguous catalog/policy ordering is resolved deterministically by UTF-8 byte order. Catalog deduplication and requested-name inventory distinguish canonical-equivalent byte spellings. The inventory includes base styles, every stored run and empty field runs, with page/node/run provenance. It never mutates the diagram or rewrites requested names, source indices or opaque font cells. It does not claim glyph coverage or layout equivalence; the native font renderer has not been changed.

No provisional transaction, calculation or scene API is consumed. Native integration obtains a current committed snapshot, revalidates eligibility, commits the candidate through `replaceInEditor`, and navigates using accepted retained scene/runtime identity. Results remain bound to their per-editor controller and exact accepted input; model IDs alone are not a document-instance identity. The logical-source preview avoids editor-only empty field placeholders. Any future direct inline-text selection integration must map those placeholders explicitly.
