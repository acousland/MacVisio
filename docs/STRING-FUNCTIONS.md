# ShapeSheet string functions

The typed ShapeSheet evaluator supports a bounded subset of Visio's documented string functions: `LEN`, `LEFT`, `RIGHT`, `MID`, `FIND`, `REPLACE`, `SUBSTITUTE`, `REPT`, `INDEX`, `CHAR`, `UNICHAR`, and `STRSAMEEX`. It also supports `STRSAME`, `UPPER`, `LOWER`, and `TRIM`.

`INDEX(index, list[, delimiter[, errorvalue]])` selects a zero-based, delimiter-separated item. The delimiter defaults to `;`; consecutive, leading and trailing delimiters represent empty items. An omitted delimiter can be written as an empty argument when supplying `errorvalue`, as in `INDEX(54,";1;2;3;",,"ERROR")`. An out-of-range index returns an empty string unless `errorvalue` is supplied. This implementation accepts finite whole-number indexes and nonempty delimiters; it rejects fractional or nonnumeric indexes and an explicit empty delimiter rather than guessing Visio coercions.

`STRSAMEEX` supports invariant locale `0`, ASCII text, and comparison flags `0` (case-sensitive) or `1` (ignore case). Microsoft's Visio file-format specification defines the function's locale ID and flags as .NET globalization comparison options. Locale-specific comparisons, non-ASCII collation, and the other defined flags (`0x02`, `0x04`, `0x10000`, and `0x20000`) are unsupported because Foundation does not provide the same .NET comparison contract. Negative or fractional locale/flag values and unknown flag bits return `FALSE`. Positive nonzero locale IDs produce an unsupported-function diagnostic; the evaluator does not try to classify every Windows LCID on macOS.

The documented defaults and argument rules are followed where stated: `LEFT` and `RIGHT` default to one character; `FIND` defaults to position 1 and is case-sensitive unless its fourth argument is true; `SUBSTITUTE` is case-sensitive by default and can replace every occurrence or one selected occurrence; and `REPT` truncates a fractional repeat count toward zero. `FIND` itself provides the case-insensitive search option, so there is no separate `SEARCH` implementation. Microsoft's Visio function reference lists `FIND`, `CHAR`, and `UNICHAR`, but not `SEARCH` or `CODE`.

The evaluator uses UTF-16 code-unit positions and lengths, matching the existing `LEN` behavior and the string representation used at the Visio COM boundary. This has not yet been compared against Windows Visio for supplementary characters. Results that would split a UTF-16 surrogate pair fail with a calculation issue because Swift strings cannot retain an unpaired surrogate. A combining mark can be selected independently from its base character, consistent with UTF-16 positions. Counts and positions other than `REPT` must be whole numbers in this subset. `MID` with a negative count and `SUBSTITUTE` with empty `old_text` fail rather than guessing at underspecified behavior. `REPLACE` clips its selected range at the end of the source text.

Every input string already has a 1,000,000-byte evaluator limit, and these functions check predicted output size before building strings. Text searches also reject a source and pattern whose UTF-16 lengths exceed the bounded search-work product. `REPT` of empty text returns empty text without iterating its requested count. `CHAR` is supported for codes 1 through 127; codes 128 through 255 depend on the Windows ANSI code page and are left unsupported on macOS. `UNICHAR` supports Unicode scalar values from 1 through 65,535 and rejects surrogate values. The docs describe this upper range but do not specify behavior for surrogate code points.

The test fixture [`visio-string-functions-boundaries.json`](../Tests/MacVisioTests/Fixtures/visio-string-functions-boundaries.json) lists formulas for checking indexing and edge behavior with Windows Visio through `CellsU.FormulaU`. On Windows with Visio installed, run `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows/Probe-ShapeSheetStrings.ps1`; the script creates a separate invisible Visio instance and emits JSON with each cell's error code, returned text and exact UTF-16 units.
