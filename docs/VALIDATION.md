# Validation — 14 October 2026

## Delivered milestone

Version 0.19.0 is a native arm64 Swift/AppKit application built with Swift 6.4 / Xcode 27 on this Apple Silicon Mac. It speeds up VSDX opening while retaining Sparkle updates; see [OPEN-PERFORMANCE.md](OPEN-PERFORMANCE.md) and [DISTRIBUTION.md](DISTRIBUTION.md). The full Visio port remains unfinished; the precise gaps are listed in [COMPATIBILITY.md](COMPATIBILITY.md). **Binary VSD writing is experimental**, with independent-parser coverage but no Microsoft Visio acceptance tests. See [BINARY-VSD.md](BINARY-VSD.md).

The packaged app requires macOS **27.0**, reflecting the actual deployment requirement of the Homebrew-built legacy reader and libraries. The Swift target alone is macOS 13. Earlier systems and Intel Macs were not tested. The bundle includes both `vsd2xhtml` and `vss2xhtml`, six relocated native libraries (libvisio 0.1.11, librevenge 0.0.6 and ICU 78.3), statically linked ZIPFoundation 0.9.20 and Sparkle 2.10.0. Licenses and source locations accompany it. No Homebrew library paths remain in bundled Mach-O dependency references. All relative dependencies resolve inside the bundle. The distribution Developer ID signature passes `codesign --verify --deep --strict`.

## Testing limits

No Windows Visio installation has been run. VSDX files have not been opened, edited and saved in Microsoft Visio. The native editor lacks many features of the requested port. Preservation of an opaque package part does not implement its functionality. External VSD graphics conversion loses legacy semantics. The experimental binary writer regenerates saved graphics/text and native metadata, with incomplete public formula/master/data/glue semantics and unresolved Windows payload fields. Full ShapeSheet, master/solution behavior, fields/advanced text layout, dynamic backgrounds, engineering measurement tools, advanced geometry/effects, automation and integrations remain incomplete.

Printing, recovery dialogs and interactive save/open/stencil/property panels have not been manually exercised. Performance across large real-world drawings and portability across older macOS releases/other architectures are not established. Passing these tests supports the delivered editing milestone; it does not satisfy the complete-port acceptance target.

## Additional independent compound-file checks

`build/format-venv/bin/python scripts/verify-binary-cfb.py` uses development-only **olefile 0.47** to check all five generated VSD examples. It verifies that parsing reports no CFB defects, the root class ID and public Visio headers match expectations, and directory red/black trees have valid ordering, coloring and equal black height. See `build/binary-cfb-verification.json`. To reproduce this extra check:

```sh
python3 -m venv build/format-venv
build/format-venv/bin/python -m pip install olefile==0.47
build/format-venv/bin/python scripts/verify-binary-cfb.py
```

This extra dependency is not bundled into the application. A detailed [binary-format evidence ledger](VSD-FORMAT-EVIDENCE.md) binds the implementation observations to fixture hashes and parser source. A prototype render showed that the intermediate SVG route reduces some text alignment/line wrapping, so rendered-preview equivalence is not asserted. Public binary cubic control points and BMP bytes/pixels have stronger explicit regression checks.
