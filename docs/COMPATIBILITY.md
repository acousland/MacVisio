# Visio compatibility — 0.20 development

The requested acceptance target is a native macOS application with every Visio Professional 2019 function and read/write support for both binary VSD and VSDX. **That target is not met.** The ISO supplies Windows installation artifacts rather than a source project that can be recompiled for macOS.

“Preserved” means a source part or XML element remains in an imported VSDX package. It does not mean MacVisio displays, recalculates or edits that feature correctly. A supported edit may change related XML, including formatting runs when text is replaced and connector geometry when endpoints move. Always evaluate representative drawings before adopting an editing workflow.

The current development milestone adds bounded [string functions](STRING-FUNCTIONS.md), [obstacle-aware native orthogonal routing](ORTHOGONAL-ROUTING.md), Shape Data validation/editors including ISO Type 5 dates/date-times and finite numeric Type 6 duration-day and Type 7 currency values, layer color/transparency and partial layer-aware Snap/Glue interaction, plus VSDX theme/variation import, selected RGB palette lookup, bounded `THEMEVAL`/`THEMEPROP`, `THEMEGUARD`, `ISTHEMED`, `CEILING`/`FLOOR`, optional-fuzz `SIGN`, and `RGB`/`HSL` index lookup for colors already present in the evaluator's palette, typed theme colors with selected HSL/RGB component calculations, and retained/evaluated page ShapeSheet cells. Shape Data `Format` pictures remain opaque; theme color calculations use a bounded function set and existing palette/theme data. Full custom color palette allocation and merging remain open. An installer-wide [ShapeSheet audit](SHAPESHEET-AUDIT.md) counts 4.87 million page-model formulas and 5.60 million raw formula cells in XML package parts across 856 libraries/templates; the latter is a syntax inventory, not evaluated behavior. Non-palette theme values and full theme rendering remain major gaps. Imported cached routes retain their existing handling. String comparison and formatting behavior remain explicitly bounded; these additions do not complete ShapeSheet, Shape Data, layer or routing parity.

A [public-only synthetic comparison corpus](INTERCHANGE-CORPUS.md) and Windows guest automation now exist and have run against the user's existing QEMU/Lima guest. The run reaches Windows 11 but fails at COM activation because Visio is not installed or registered; no Visio acceptance is claimed. Results and installation evidence are in [Windows validation](WINDOWS-VALIDATION.md). Neither generated expectations nor successful local parser checks establish Windows acceptance.

Supported functions currently include IF/IFERROR, `INDEX`, ISTHEMED, GUARD/THEMEGUARD, bounded `THEMEVAL` and `THEMEPROP`, SETATREF/SETATREFEXPR/SETATREFEVAL, BOUND, PI, ABS, SQRT, trigonometric functions, LN/EXP, INT/SIGN, ROUND, CEILING/FLOOR, `BITAND`/`BITOR`/`BITXOR` for unitless whole-number operands from 0 through 65535, RGB palette lookup, MODULUS, DEG/RAD, POW, MIN/MAX/SUM and AND/OR/NOT. Units include inches, points, common metric/imperial lengths, radians/degrees and percent. This evaluator is not a complete ShapeSheet engine. Unsupported expressions produce a calculation issue and preserve cached imported geometry. See [ShapeSheet numeric functions](NUMERIC-FUNCTIONS.md).

Inputs are bounded: package 100 MB compressed, 128 MB expanded, 16 MB per part and 10,000 entries. XML external entities/DTDs and unsafe package paths are rejected. These limits may exclude legitimate large Visio documents. Macros, imported actions and data links do not execute.

The current regression corpus contains real libvisio VSD/VSDX fixtures and independently constructed public XML packages. It cannot prove every Visio feature, version or file round trip. Source references and fixture licenses are in `Tests/MacVisioTests/Fixtures/README.txt` and the packaged app's license folder.

Version 0.3 includes native VSD Save As/export and command-line conversion. Native-model metadata is not evidence of full public binary compatibility; independent tests explicitly read generated binary content without that metadata. Original binary sources retained during VSDX conversion are stored as bounded package segments.

The historical 0.4 milestone added page/background editing and composed exports. At that milestone, cached coordinates shared a physical lower-left origin without automatic stretching; scale composition was completed in 0.9, while dynamic background formulas remain incomplete.

Version 0.5 expands omitted master subshapes, including multi-root masters, and saves minimal local overrides with deletion tombstones. Unedited source masters remain unchanged. Cached master geometry is used on import; full inherited expression evaluation and automatic instance resizing are still incomplete.

Version 0.6 records connector group parents and exports parent-coordinate geometry in VSDX and experimental VSD. Group moves preserve unchanged local connector XML. Repeated resize drags use the original snapshot. Cached master members materialize when ungrouped; their original definitions remain in the package, but full inherited formula/action behavior is not implemented. ID allocation stays within unsigned 32-bit bounds, and copied numeric references avoid quoted literals.

Version 0.7 adds Connection section rows and port-specific `Connect` targets. Port endpoints follow local geometry through rotation/reflection and hierarchy. Native VSD metadata retains port editing state; its public binary stream currently contains the resulting cached graphics, not complete port/glue declarations. Windows acceptance remains unverified.

Version 0.8 exercises actual installer stencil/template bytes. Cached elliptical arcs are approximated with cubic segments through the specified arc point; this improves the Document master's visible curved border. Deleted master overrides with repeated sentinel IDs are excluded from live-object identifier checks, while their source tombstones remain preserved. Unnamed/repeated layer names receive distinct native display names without changing unedited public XML. The broad import scan establishes parser coverage rather than visual or behavioral parity.

Version 0.9 retains drawing coordinates while applying PageScale/DrawingScale to paper rendering and bounds. Font size and line weight remain paper quantities. Signed geometry uses a positive native frame with an explicit source origin, preserving raw flip/rotation/pin transforms. The complete installer scan imports 856/856 files. ShapeSheet geometry formulas are materialized when a cached fragment crosses measured/unmeasured spaces; full master behavior remains incomplete. Existing pre-0.9 VSDX metadata containing flips is reimported from public XML. Older native JSON with cached flipped frames should be reimported from its public VSDX source before relying on the corrected coordinates.

Version 0.10 models character/paragraph runs, resolves modern font declarations by ordered NameU entries, protects standalone line breaks during XML edits and exports mixed public text in both drawing formats. Source-preserving edits retain master definitions and unknown row cells. Fresh public exports are independently parsed; exact Windows layout and advanced field/paragraph behavior remain unverified or incomplete.

Version 0.11 retains field rows and insertion markers, updates supported formulas after edits, resolves shared background page information in the foreground context and adds cached public binary field records. VSD field expressions remain incomplete; public binary records carry saved string values. Detailed boundaries are in [TEXT-FIELDS.md](TEXT-FIELDS.md).

Version 0.12 retains Geometry definitions, recalculates supported numeric dependencies and exports public VSDX formulas rather than flattening every path. Local formula overrides retain page references, inherited references map to their instance and changed rows patch minimally. Experimental VSD carries calculated public graphics rather than geometry expressions. Full geometry, controls and master behavior remain incomplete.

Version 0.13 renders and recalculates supported NURBS/polyline data, exports public binary saved-curve records, recovers older compound caches and preserves unchanged page-index/relationship bytes during content edits. An actual installer staircase exercises saved NURBS geometry. This does not establish full stencil behaviour, exact curve/Windows parity or binary expression compatibility.

Version 0.14 fixes serialized knot precision and close-span evaluation. The effective audit of all 26 previously affected files changes from 347 NURBS failures to zero. Compound caches retain full numeric precision and older geometry-cache versions recover without dropping native identities or preserved source bytes. See [KNOT-PRECISION.md](KNOT-PRECISION.md). Full curve/function/stencil behaviour and Windows compatibility remain unproven.

Version 0.15 calculates spline sequences, preserves editable public VSDX rows and emits saved experimental binary spline records. Older native control-polygon caches recover from retained definitions. World-master spline rows now pass the effective geometry audit. Complete geometry/control/master behaviour, binary expressions and Windows acceptance remain unfinished.

Version 0.16 adds native control-handle editing, public Control section preservation, constrained dragging and BOUND/SETATREF calculations. A real installer Parallelogram verifies control-driven geometry edits. Full control dynamics/gluing, stencil behavior, ShapeSheet semantics, specialist solutions and binary/Windows compatibility remain unfinished.

Version 0.17 adds typed text/context dependencies, SHAPETEXT and native TEXTWIDTH/TEXTHEIGHT calculations, supported text-transform and tooltip updates, cached paragraph spacing/indents, typed cell editing, exact snapshot Undo/Redo, implicit internal-unit literals and REF errors. The STRSAME case flag is corrected. Analytics and staircase installer tests exercise actual formulas; full text/unit/master/control behavior and Windows acceptance remain unfinished.
